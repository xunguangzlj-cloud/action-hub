行动中枢：云服务配置指引

适用版本：安卓 1.1.1 / 对应新版网页。文档核对日期：2026-09-03。

本文面向第一次配置同步的新用户，采用 uniCloud 阿里云服务空间 + 内置云数据库 + 普通云函数。已有设备能够正常同步的用户不需要重新部署，更不要随意重新生成密钥。原服务已升级到基础版的，继续使用原空间即可。

本次仅增加文档与部署材料，不修改任何人的现有云空间、数据库、套餐或密钥。不同云厂商的菜单、限制和计费不完全相同，本文不保证其他云厂商可按原样部署。

一、先分清四样东西

名称 作用 在哪里使用
服务空间 容纳你自己的数据库和云函数 uniCloud 控制台、HBuilderX 关联空间
工作台网页地址 打开行动中枢界面 电脑/手机浏览器地址栏
云函数 HTTPS 地址 让应用交换同步数据 应用“数据 → 云函数地址”
同步密钥 验证是否允许访问这份数据 云函数环境变量及两台设备的“同步密钥”

一个空间里的这套模板只管理一份个人数据，不是多用户注册系统。两台设备填同一个接口地址、同一个密钥，就访问同一份数据。不要让无关人员共用；不要把密钥写进 GitHub、网页代码、截图或聊天记录。

二、准备材料

  1. 一个你自己控制的 DCloud 账号，按控制台提示完成所需认证。
  2. 电脑上的 HBuilderX，用于上传数据库结构和云函数。已有安装可直接使用。
  3. 从本项目 v1.1.1 发布页 下载补充包 action-hub-cloud-setup-20260903.zip 并解压。
  4. 安卓手机安装原来的 1.1.1 APK；此补充包不包含新 APK，也不要求重新安装应用。

三、创建服务空间

  1. 登录 uniCloud 控制台。
  2. 在服务空间列表创建自己的 阿里云 空间，例如 action-hub-personal。名称由你决定，不要套用其他人的空间 ID。
  3. 查看套餐及资源限制后再确认开通。官方目前提供阿里云开发测试免费空间；是否可申请、有效期、续期与付费套餐，以你的控制台为准。免费不等于无限量或永久有效。官方计费说明
  4. 等空间创建完成，再点进它。后续部署数据库和云函数时，始终核对是同一个空间。

完成标志： 控制台能看到所选空间，以及其中的云数据库、云函数/云对象等入口。

不要为了体验同步而默认开通按量付费、自动续费或升级套餐；任何付费选项应由你检查价格后决定。

四、在 HBuilderX 关联空间

  1. 登录 HBuilderX，账号与控制台一致。
  2. 选择“文件 → 新建 → 项目”，创建普通 uni-app 项目，勾选“启用 uniCloud”，供应商选择阿里云。项目名称例如 action-hub-cloud。
  3. 在项目的 uniCloud 目录右键，选择“关联云服务空间”或类似名称，选中第三节创建的空间。
  4. 将补充包 uniCloud-aliyun 目录中的 cloudfunctions 和 database，合并到这个新项目对应的阿里云 uniCloud 目录中。保持 action-sync/index.js 与 action-sync/package.json 同层，不要重复套一层 uniCloud-aliyun。
  5. 如提示缺少 appid，在新项目 manifest.json 的基础配置中获取自己的 uni-app 应用标识。不要填写别人的标识，也不要删除旧项目来解决问题。

HBuilderX 中目录可能显示为带供应商/空间名称的虚拟 uniCloud 目录；以关联结果为准。官方的创建、关联操作见 uniCloud 快速上手。

完成标志： 关联空间名称正确，项目中能找到 cloudfunctions/action-sync 和 database/action-hub-state.schema.json。

这里只用新项目上传云端材料，不需要云打包安卓，也不要把新项目默认首页当作行动中枢网页上传。

五、建立数据库集合与权限

  1. 在项目中右键 action-hub-state.schema.json，选择上传 Schema 到关联服务空间。
  2. 去控制台“云数据库”确认存在集合 action-hub-state。如尚未建立，可先创建同名集合，再上传 Schema。
  3. 在该集合的“表结构 / Schema”中确认 read、create、update、delete 四项权限都是 false。
  4. 暂时不要手工插入真实任务或创建空记录。云函数在首次收到新增内容时会建立固定的 primary 文档。

此模板使用内置数据库和 uniCloud.database() 的云端接口；不需要另外购买、绑定扩展 MongoDB，也不需要 Redis、对象存储或外部数据库密码。

Schema 限制客户端直接访问；云端函数负责验证同步密钥后读写。不要为排错而把四项权限全部改为 true。官方 Schema 说明

完成标志： 集合名称正确，表结构已上传，四项权限关闭。仅保存本地 Schema 不代表已经部署到云端。

六、上传普通云函数

  1. 在 HBuilderX 中找到 cloudfunctions/action-sync，它是普通 JavaScript 云函数，不是云对象。
  2. 右键该文件夹，选择上传部署到关联空间的菜单，等待成功提示。
  3. 在控制台所选空间的 “云函数/云对象”（有的界面显示“云函数”）列表中，找到 action-sync，点击详情。
  4. 核对配置：访问路径 /action-sync、超时 10 秒、内存 128 MB。若当前平台不提供该内存档位，应按控制台可选项和预算调整；不要把预置档位理解为所有平台必然支持。
  5. 运行环境选择当前平台支持的、能运行本模板语法的 Node.js 版本；本模板使用可选链等语法，不应照抄旧教程中的 Node.js 8。

代码使用内置 crypto 与 uniCloud 数据库能力，没有需自行申请的 AI API Key，也没有额外 npm 依赖。不需要配置定时触发器、保活任务或每分钟调用的定时器。配置与部署行为见 官方云函数说明。

完成标志： 控制台列表中有 action-sync，本次上传成功。若你正在“云数据库”或“扩展数据库”页，看不到云函数是正常的，请返回服务空间菜单切换入口。

七、生成并配置同步密钥

新用户生成一次

在行动中枢的“数据”中点击“生成强密钥”，再点“复制密钥”，安全保存。此时不要急着点“保存并测试”，先完成云端配置。

已有同步服务的用户应沿用原密钥，不要再生成。点击“生成强密钥”只改变输入框，不会自动修改云端，也不会自动替另一设备更新。

写入云端环境变量

  1. 控制台进入所选空间 → 云函数/云对象 → action-sync 详情。
  2. 找到“环境变量”，点击“编辑”。
  3. 新增一项：名称为 ACTION_HUB_SYNC_KEY，值为刚才生成的完整密钥。
  4. 保存。名称和值分开填写，值中不要加入 ACTION_HUB_SYNC_KEY=，也不要额外包引号。

官方说明中，控制台保存环境变量后实时生效；HBuilderX 也有环境变量入口，但会创建本地 .env 文件。为避免意外上传私人信息，本文推荐在控制台配置，且绝不把 .env 提交到公开仓库。官方环境变量说明

完成标志： 环境变量名称存在且拼写正确。不要为了验证而把密钥输出到函数日志。此密钥不是 APK 签名密码、DCloud 登录密码或服务空间 ID。

八、开启云函数 HTTP 访问

  1. 在 action-sync 详情找到“URL 化 / HTTP 访问地址 / 访问路径”配置。
  2. 将路径设为 /action-sync。包内 package.json 已声明这个路径，若上传后已生效，不必重复改动。
  3. 保存并复制控制台生成的 完整 HTTPS 地址，不要自行拼接域名或空间 ID。
  4. 保留这个地址，稍后填入应用“云函数地址”。

这是数据接口，不是网页。浏览器地址栏直接打开会发 GET；模板只接受 POST 同步和 OPTIONS 预检，GET 不会展示行动中枢界面。阿里云默认 URL 化域名直接打开还可能触发下载，这不等于接口坏了。以应用的“保存并测试”结果为准。官方 URL 化说明

不要删掉模板里的集成响应格式、状态码和跨域响应头。接口公开可访问不代表数据公开，密钥校验仍然必需。错误密钥应返回 401，不能关闭校验来解决错误。

九、部署电脑和手机可访问的网页

只使用安卓安装版、不需要浏览器访问的，可跳过网页托管；电脑浏览器需要一个自己的工作台网页地址。

  1. 控制台选择“前端网页托管”，选择自己的目标空间；如未开通，先检查提示中的费用和限制。
  2. 将补充包 web 内的六个文件上传到专门用于行动中枢的网站根目录：index.html、app.js、styles.css、manifest.webmanifest、sw.js、icon.svg。
  3. 网站首页设为 index.html，复制托管控制台提供的 HTTPS 网站地址。
  4. 用电脑或手机浏览器打开，确认出现“行动中枢”，而不是目录列表或默认 uni-app 首页。
  5. 如果使用自定义域名，按服务提供方要求配置域名、HTTPS 与相应备案。域名本身也可能收费。

不要把云函数代码、Schema、密钥、证书、APK 或整个 HBuilderX 项目上传为网站资源。如果目标网站已有别的内容，先备份或使用独立站点，不要直接覆盖其根目录。

阿里云默认测试域名有访问频率与每日公网 IP 等限制；遇到 ClientIpNotAllowed，应检查托管域名的 IP 限制，换手机网络可能改变公网 IP。长期或公开使用不应承诺测试域名永远稳定，正式域名的要求和最新限制请看 官方前端网页托管说明。

网页域名与云函数域名不同，浏览器会进行跨域检查。在服务空间“跨域配置 / Web 安全域名”中核对实际工作台域名；自定义域名、非默认端口或本地开发地址需按控制台规则配置。优先只填写实际使用的来源，不要靠安装跨域插件或关闭浏览器安全保护来解决同步问题。官方 Web 发行与跨域配置

完成标志： 工作台 HTTPS 地址能打开；它与第八节的云函数 HTTPS 地址是两种不同用途的地址。

十、连接电脑与手机，并验收

两端分别配置

电脑打开工作台网页，手机打开安卓安装版或相同网页。每一端均进入“数据”：

  • “云函数地址”：填第八节的完整 HTTPS 接口地址。
  • “同步密钥”：填第七节的同一密钥，去掉误粘贴的空格和换行。
  • 点击“保存并测试”，等待“同步完成”。

这里只需地址与密钥，不需要在应用中输入 DCloud 密码、数据库账号或 APK 证书。手机网页与安卓安装版是两份独立本机存储，应各自配置，不能因为同一台手机就认为已经互通。

用无敏感内容验收

  1. 电脑新建一条“电脑同步测试”，点击保存，再点“数据 → 立即同步”，等成功。
  2. 手机点“立即同步”，确认能找到“电脑同步测试”。
  3. 手机修改这条记录，保存并同步；电脑再同步，确认修改出现。
  4. 如果测试“一句话记录”，应在独立文件夹里查找；也可以用搜索定位。
  5. 需要确认离线能力时，断网记录一条测试事项，恢复联网并保持应用打开，再依次同步两端。
  6. 测试成功后可手动删除测试记录并同步。不要用批量清空数据库的方法收尾。

通过标准： 两个方向都能交换记录，内容和归类一致，控制台无持续错误。全过程请避开两端同时修改同一记录，并在同步结束后再继续编辑。

应用有约 1 分钟的编辑后自动同步等待；启动检查也有节流，且没有持续实时推送。设备 A 同步成功后，仍需设备 B 再读取。换设备前后各点一次“立即同步”最明确。

十一、常见问题按这里排查

现象 检查与处理
找不到云函数 返回具体服务空间，打开“云函数/云对象”，不是“云数据库/扩展数据库”
控制台没有 action-sync 检查 HBuilderX 关联空间和上传日志；本地保存不等于已上传
同步密钥不正确 / 401 云端环境变量、电脑、手机三处必须一致；大小写和空格都要检查；不要随意重新生成
地址直接打开下载文件或显示只支持 POST 可能是默认域名/GET 访问表现；用应用“保存并测试”，不要把接口当工作台
Failed to fetch 先检查联网、HTTPS 地址、空间状态，再查浏览器跨域及预检；不要清空数据或关闭浏览器安全保护
404 检查完整云函数 URL、URL 化路径、函数是否上传到正确空间
405 检查调用方法；正常应用发送 POST，地址栏 GET 不是有效同步测试
云端同步失败 / 500 在同一空间查看函数日志，检查 action-hub-state 是否存在、是否使用内置数据库；日志发给他人前需脱敏
429 / resource exhausted / 等待额度恢复 查看用量和真实错误原因，区分请求限频、套餐额度或资源异常，不要仅根据页面“免费”字样判断
网页提示 ClientIpNotAllowed 检查前端网页托管测试域名 IP 限制，不是优先去改同步密钥
电脑有变化，手机没有 先同步更新端，再同步另一端；核对地址、密钥、程序版本和当前文件夹/筛选
更新网页后仍是旧界面 按控制台刷新静态资源缓存；关闭原工作台全部标签页后重开，先不要清除站点数据

如果所有操作仍失败，保存完整错误与发生时间，结合云函数日志排查。本模板的部分旧提示会把数据库错误归为“免费额度”，这不是对你实际套餐或根因的可靠判定。

十二、维护、费用与安全边界

  • 每周导出一次 JSON 备份；修改服务配置和换设备前再备份。同步会合并修改和删除，不能替代历史备份。
  • 云函数调用、运行资源、流量和数据库读写分别计量；一次调用不一定只算一次数据库操作，无变化也可能发生读取。不要为“自动同步”额外建立高频定时任务。官方用量说明
  • 免费空间按官方规则管理有效期，付费基础版按自己的套餐续费；升级套餐不会自动修复地址、权限或跨域错误。具体价格、限额和恢复周期以控制台为准。官方计费说明
  • 云端存储的是任务、位置等记录，不是端到端加密保险箱；云服务管理员可以读取数据库。不要上传不适合存入该服务的数据。
  • 记录按整条修改时间合并，当前不是多人协同系统；不要让多个使用者同时写入同一套服务，保持设备时钟准确。
  • 密钥泄露后需在你自己的控制台和所有设备协调更换。更换不会自动退出已离线保存数据的他人设备，也不能收回已泄露的数据。
  • URL 化接口暴露在互联网，错误密钥仍可能消耗请求资源。若遭滥用，应先检查用量并限制/暂停该接口，保留本机备份；不要把“带密钥”理解为绝不会产生异常费用。
  • 不要公开 .env、密钥、证书、账号会话、个人备份；也不要把本项目部署者的私有空间当作公共服务。

十三、这份指引验证到了哪里

补充包复用本项目现有同步云函数、数据库 Schema 和网页资源，不改变它们的业务逻辑。已核对官方配置文档，并在本地模拟数据库检查鉴权和同步协议；本次没有替你新开云空间、购买套餐或执行一次全新的云端部署。

实际开通、网络连通和不同套餐限制，仍须按第十节在你自己的空间与两台设备上验收。现有服务已能同步的，不需要为阅读本指引重建任何资源。
